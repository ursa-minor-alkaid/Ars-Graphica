# 工作流一：文字描述 → 图形

用户输入文字描述，输出满足描述的独立 SVG 文件。几何与定位规则以 `guides/precision-svg.md` 为准，本文件负责把描述转成图形结构。

## 1. 需求解析

1. 显式类型：描述中出现"流程图""架构图""柱状图""时序图"等类型词，或描述本身已确定结构（"A 包含 B 和 C"），按其执行
2. 隐式类型：未指定类型时，按内容特征选择：
   - 事物间的结构或依赖 → 结构图/架构图
   - 步骤先后与分支 → 流程图
   - 多方交互的先后顺序 → 时序图
   - 数值比较、趋势、构成 → 数据图表
   - 某事物如何运转 → 机制图
   - 选项取舍 → 对比图
3. 类型选择在回复中一句话说明，供用户确认或纠正
4. 信息缺口：描述中缺少必要数据（如图表的具体数值、流程的分支去向）时，先提问补全再绘制；不得虚构数据。可以合理推断的结构细节（如自动布局方向）直接决定

## 2. 通用构图原则

- 单一焦点：每幅图恰好一个视觉焦点（关键路径、最高值、核心模块、推荐项），用品牌色或位置强调。全部元素同等重要时，先与描述核对哪个是主角
- 可读性优先于完整性：放不下就分组、拆分或简化，小而清楚优于大而拥挤
- 方向语义：上下 = 层级与过程；左右 = 时间与依赖。全图一个主方向，禁止混用
- 复杂度预算：主节点 2~5 个；水平单排 ≤ 4 个框；超过则分组（容器）或拆分为多幅
- 复用 `examples/` 中同类型示例作为起手骨架，替换内容后按 precision-svg 重算全部坐标

## 3. 分类型构图规则

### 3.1 流程图

- 主路径 3~5 步，单一方向
- 起止节点用胶囊形（`rx = h/2`）；处理节点用圆角矩形（`rx = 8`）；决策节点用圆角菱形（路径转角处做半径 ≥ 6 的圆角，禁止尖角）
- 每个分支独占一条出线轨道，分支标签（1~3 词）放胶囊内，置于线的上方或下方
- 决策的两条出线从菱形左右两端或下端引出，禁止两条线共用一段起点
- 并行步骤：同一阶段的多步并排放置，阶段间连线从阶段边界（不可见的分组框）引出

### 3.2 时序图 / 状态图

- 参与者各占一列（顶部为名称标签，下方为 lifeline 虚线）
- 消息行距 ≥ 72；仅状态的紧凑行距 ≥ 56；禁止同一 y 坐标复用给状态标记、消息线与消息标签
- 消息箭头可水平可斜线；收发双方在不同行时用斜线，方向由端点自然决定
- 消息标签置于双方之间的胶囊中，偏移箭头 14~20 单位；双向消息对交替上下偏移标签
- 回线（返回消息）用浅弧线绕行，弧线不得穿过任何 lifeline 标签与消息标签
- 状态标签放在 lifeline 旁，禁止放在消息箭头上
- 协议阶段多时（如握手 + 拆除）拆分为多段面板，禁止挤进同一坐标系

### 3.3 数据图表

纯 SVG 手绘，禁止引入 Chart.js 或任何外部库。

- 坐标系：轴线用 `--text-muted`；网格线用 `--border`，仅水平网格（条形图仅垂直网格），禁止全格网
- 刻度：均匀取值（0、25%、50%...），刻度标签 12px，`text-anchor` 按轴位置决定（y 轴标签 `end`，x 轴标签 `middle`）
- 数值标签：条形标在柱顶上方（12px，middle 锚点，基线 = 柱顶 - 4）；折线点标在点上方（避让重叠时移至下方或左右）
- 图例：置于图表上方右侧或下方居中；色块 12×12 圆角 3 + 标签 12px，行距 8；超过 4 项收敛类别
- 系列：同源系列按 series-1..4 顺序着色；单系列用 series-1；双系列必须明度差明显
- 数据诚实：数值带单位；同图舍入位数一致；估算值加"约"或星标说明；负值不进饼图与漏斗；类别 > 5 时收敛为 Top N + Other
- 饼/环/雷达：图形容器保持自然纵横比居中，不拉伸全宽；环图中心可放一个主数值（text-title，全图唯一）
- 零基线：条形图必须从零起量

### 3.4 机制图

- 画机制本身，禁止画"关于机制的图"。画哈希碰撞的实际桶与链表结构；禁止画一个写"哈希函数"的盒子加一根箭头了事
- 判定标准：删掉全部文字标签后，图形仍能传达大致含义
- 构图顺序：外轮廓/边界 → 内部结构 → 输入输出 → 状态指示 → 标签
- 物理量语义色：暖色 = 高能量/活跃/高温；冷色 = 低能量/静态/低温；渐变仅限连续变量（温度、压力、浓度）
- 步骤编号用圆形数字徽章，≤ 6 步
- 单帧截面用一幅图；多阶段过程用 2~3 个并列状态帧（左→右），或单图加编号步骤

### 3.5 对比图

- 三种布局：决策矩阵（维度 × 选项的表格网格，≥3 维 × ≥3 选项）、选项卡片（2~4 选项各一张卡，3~5 维度行）、优缺点（二元对照）
- 选项 2~4 个、维度 3~5 个，超限先收敛
- 必须呈现两面：优势与代价/风险同时出现，禁止只画优点
- 推荐项用品牌描边 + 徽章标记；其余保持中性
- 卡片内部：标题（text-title）+ 维度行（label 左 + 值右），分隔线分段，禁止卡中卡

### 3.6 结构图 / 架构图

- 块类型四种：中性模块（普通组件）、品牌模块（核心，全图唯一）、边界容器（运行/归属范围，虚线描边）、外部块（用户、第三方、输入输出）
- 嵌套 ≤ 2~3 层；容器先定位，内部节点每侧留 ≥ 20 内边距
- 外部输入输出置于容器外，连线从容器边缘进出
- 连线类型三种：中性实线（标准依赖）、品牌色（焦点路径）、虚线（弱依赖/可选）；每图 ≤ 2 种线型
- 模块 > 6 个时先分组；连线 > 8 条时收敛或改为关系表

## 4. 颜色应用

按 `tokens/visual-tokens.md` 的角色规则执行：

- 默认姿态：中性面 + 中性连线 + 一个品牌焦点（节点描边或焦点路径）
- 同源多类别：chart-series 阶梯，上限 4 + Other
- 语义色门禁：仅显式状态/风险/健康编码；描述中的"成功""失败"等词不触发语义色
- token 色值未填写时使用灰阶占位配色并在回复中说明

## 5. 文字密度

- 节点标签 2~5 词；卡片标题 6~10 词；副标题 ≤ 5 词
- 连线标签 1~3 词，显而易见的关系省略标签
- 标题大小写：中文不适用；英文用 sentence case
- 代码、路径、命令用 `--font-mono`
- 详细解释写进对话回复，不进图。图内只保留定位所需的最少文字

## 6. 输出

1. 按 precision-svg 完成坐标计划与自检
2. 写出 SVG 文件（命名：用户指定名或按内容语义，如 `login-flow.svg`）
3. 回复中报告：文件路径、所选图形类型、焦点是什么；token 未填时说明占位配色
